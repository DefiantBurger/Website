## Class Scheduler

Semester planner that validates prerequisites and draws them as a dependency graph.

- `GET /api/scheduler/default-schedule/` → `backend/app/static/json/my_courses.json`
- `GET /api/scheduler/course-data/` → `backend/app/static/json/course_data.json`

### Data Model

**Schedule.** Keys are `precollege` (credit already earned) or a term plus two-digit year (`fall24`, `winter25`; terms are `winter`, `spring`, `summer`, `fall`). Columns are always sorted by date regardless of key order; any other key is rejected. A `[n]` suffix sets the credits for a variable-credit course.

```json
{ "semesters": { "precollege": ["MATH 221"], "fall24": ["MATH 222", "PHYSICS 499[3]"] } }
```

**Catalog.** Version 2, generated by the separate `course-data-scraper` repo (its README is the full spec); any other `version` fails to load. Each course has `title`, `credits` (or `min_credits`/`max_credits`), `requires`, `requisites_text`, `not_open_with_credit_for`, and `last_taught`.

- `requires` is `null` or `{"all": [...]}`; each item of that top-level `all` is a **requirement row**. Nodes are a course code, `{"all": [...]}`, `{"any": [...]}`, or `{"atleast": k, "of": [...]}`, nested to any depth. `"concurrent": true` (only on `any`) allows same-semester enrollment for anything under it.
- `requisites_text` keeps conditions the scheduler can't check (standing, major, consent). It isn't displayed.
- `not_open_with_credit_for` is treated as symmetric, since the catalog usually lists a pair on one side only.
- `last_taught` is loaded but unused.

**Updating the catalog.** The catalog is a snapshot of [guide.wisc.edu/courses](https://guide.wisc.edu/courses/), so regenerate it each term. The scraper lives in [`course-data-scraper`](https://github.com/DefiantBurger/course-data-scraper), cloned next to this repo:

```bash
uv run main.py fetch --refresh     # re-download the subject pages
uv run main.py build               # writes output/course_data.json and output/report.md
uv run main.py diff ../PersonalWebsite/backend/app/static/json/course_data.json output/course_data.json -v
cp output/course_data.json ../PersonalWebsite/backend/app/static/json/
```

- Requisite text is parsed by a rule parser that refuses anything ambiguous; refused strings get hand-written entries in its `data/overrides.json`, and until then export with no requirements. `report.md` lists unresolved strings, stale overrides, and dropped references; check it before copying the file over.
- Non-course conditions (standing, consent, placement) and courses missing from the catalog are dropped, so a dropped alternative makes a requirement stricter.
- Unknown courses in saved plans are skipped on load, so a catalog update doesn't break old links. `my_courses.json` (the default plan) isn't generated; check it still loads cleanly after an update.

### Behavior

- **Code layout.** `catalog.ts` builds and exports schedules (each course occurrence gets a unique ID, `<course>__<n>`) and searches the catalog. `schedule.ts` holds every edit as a pure function. `store.svelte.ts` (`SchedulerStore`) holds the page state (the schedule as undo history, the catalog, selection, notices, drag state), applies edits through `store.apply()` so `history.ts` can undo/redo (100 steps), and derives everything else (graph, overlaps, problems). `UtilityScheduler.svelte` creates the store, passes it to the components, and handles loading, import/export, and the share link.
- **Requirement checks** (`logic.ts`). Each row is evaluated against a course's earliest scheduled instance: `met`, `concurrent`, `out-of-order`, or `missing`, ranked in that order. `any` takes its best child, `all` its worst, `atleast k` its k-th best. Edges are drawn from the courses that decided each row. Precollege courses count as earned, so their own requirements aren't checked. Progress is satisfied rows ÷ all rows.
- **Credit overlaps.** For a pair that can't both count, the later one is flagged and both cards show `≠`; pairs entirely in precollege are ignored.
- **Auto-detangle** reorders cards within columns (barycenter sweeps) to reduce edge crossings.
- **Share links** (`shareLink.ts`). The plan lives in the URL fragment as `#plan=v1.<base64url(deflate-raw(JSON))>`, so it never reaches the server. After the first edit, every change is written with `history.replaceState` (debounced 300 ms). Opening a link skips auto-detangle so card order is kept. Decoding is capped at 256 KB. **A new format needs a new version prefix, and the `v1` decoder must stay** so old links still open.
- **Validation** is shared by links and JSON import. Bad semester keys or a malformed file reject the whole plan; unknown courses and invalid credits are skipped and listed in a notice, so old links survive catalog changes. An undecodable link on page load shows an error and falls back to the default plan.

## File Share

Temporary file sharing keyed by an access key: files are encrypted at rest and expire after 10 minutes.

### API

`POST` bodies are `multipart/form-data`; `password` is the access key.

| Method | Path | Fields | Response |
| --- | --- | --- | --- |
| GET | `/api/fileshare/status/` | | `{activeFileCount, usedBytes, maxFileBytes, maxTotalBytes, retentionSeconds}` |
| POST | `/api/fileshare/upload/` | `file`, `password` | file record, stored at the key's next `occurrenceIndex` |
| POST | `/api/fileshare/delete/` | `password`, `occurrenceIndices` (comma-separated) | `{"deletedCount": n}`; missing indices are skipped |
| POST | `/api/fileshare/list/` | `password` | `{"files": [<file record>]}`; 404 if none |
| POST | `/api/fileshare/access/` | `password`, `occurrenceIndex` (default `1`) | the file as an `application/octet-stream` attachment |

A file record is `{occurrenceIndex, originalFilename, sizeBytes, uploadedAt, expiresAt}`.

Errors: `400` missing key/file or invalid index, `403` decryption failed, `404` no matching file, `413` file over 80 MB, `503` storage full or too many concurrent transfers.

### Behavior

- **Lookup.** The storage label is HMAC-SHA256(access key) keyed with `SECRET_KEY`, so labels can't be brute-forced without the server secret. A key's files are `<label>.json`/`.payload`, `<label>__2.*`, and so on; each upload claims its index by creating the payload exclusively, so concurrent uploads never overwrite each other.
- **Encryption.** scrypt (n=2¹⁴, r=8, p=1, random salt per file) derives an AES-256-GCM key from the access key. Files are encrypted and decrypted in 1 MiB chunks, streamed to and from disk, so a transfer's memory use doesn't grow with file size. Each chunk's nonce is its index plus a last-chunk flag, so truncated, extended, or reordered payloads fail to decrypt. A download checks the first chunk before responding; a bad later chunk ends the stream short of its `Content-Length`.
- **Limits.** 80 MB per file (under Cloudflare's 100 MB request limit), 1 GB total; the oldest files are evicted to make room, else `503`. At most 3 transfers run at once (`MAX_CONCURRENT_TRANSFERS`), leaving one of Waitress's 4 threads for other requests; a download keeps its slot until the response is fully sent.
- **Expiry.** File-share requests delete expired files, and in production a background thread (`start_expiry_sweeper`, started in `main.py`) also sweeps every minute, removing payloads left without metadata for longer than the retention period.
- **Downloads** ignore the uploader's MIME type and send `nosniff`, so uploaded HTML can't run on the site's origin.
- **UI batches.** The UI uploads one request per file, and a new batch replaces the key's previous files only after every upload succeeds; on failure it deletes what it already stored, so the previous batch survives (`lib/fileshare/replaceBatch.ts`). Indices keep counting up across batches.

## Message Board

Anonymous board where messages expire 60 seconds after posting.

| Method | Path | Body | Response |
| --- | --- | --- | --- |
| GET | `/api/messageboard/messages/` | | `{messages, serverTime, retentionSeconds, maxMessageLength}`, messages newest first |
| POST | `/api/messageboard/messages/` | JSON or form: `{"text": "..."}` | `201` with the message |

A message is `{id, text, createdAt, expiresAt}`. Errors: `400` empty, non-string, or over 280 characters after sanitizing; `413` body over 16 KB; `429` rate limit.

- **Sanitizing.** Normalizes line endings to `\n`, turns tabs into spaces, NFC-normalizes, and drops control, format (zero-width, bidi overrides), surrogate, private-use, unassigned, and line/paragraph-separator characters, except the joiner and tag characters emoji sequences need. Markup is stored as typed; the frontend renders text, never HTML. Runs of 3+ newlines collapse to 2.
- **Storage.** In-process memory behind a lock: at most 200 messages (oldest evicted), expired ones purged on every read and write, all lost on restart.
- **Rate limit.** 5 posts per 10 s per client IP (sliding window), checked before validation, so rejected posts count too.
- **Page.** Polls every 5 s while the tab is visible (and right away when it becomes visible again), and after posting. Each card counts down and disappears when it expires. Expiry is timed from `serverTime`, so a wrong local clock doesn't hide or keep messages (`lib/messageboard/board.ts`). Messages are never rendered with `{@html}`.
- **Length.** The page counts code points after NFC, like the server, so an emoji counts once. The textarea has no `maxlength`, which counts UTF-16 units.

## Adding a Utility

1. Add the route (`routeDefinitions.ts` + `routes.ts`) and the page in `frontend/src/pages/`, with its logic and API client in `frontend/src/lib/<name>/` built on `lib/api.ts`.
2. Add a card to `Utilities.svelte`.
3. Add backend routes under `/api/<name>/` in `views.py` (logic in its own module; raise an `ApiError` subclass for client errors) with tests.
4. Document it here.
